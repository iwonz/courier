# Change: Complete the illustrated Courier interface system

## Why

Courier now has a recognizable identity, but native-looking selectors and repeated use of one neutral mascot pose make the browser surfaces feel unfinished. Controls need one intentional interaction language, while Relay should explain the situation on each surface instead of acting as interchangeable decoration.

## What Changes

- Replace native-looking theme and locale selectors with accessible segmented controls owned by the shared UI kit.
- Apply one branded treatment to selects, text and number fields, password entry, checkboxes, file selection, and raw action buttons across delivery and administration surfaces.
- Introduce a locally stored illustration family that keeps Relay's identity stable while assigning context-specific wardrobe, tools, posture, and environment to installation, routing, verification, authentication, and operations scenarios.
- Recompose the landing page with section-specific illustrated briefs rather than repeating one mascot cutout.
- Add a full-width repository banner to the README and extend asset provenance, digest, accessibility, responsive, and embedded-build checks.

## Impact

This change affects presentation, local static assets, shared browser components, application markup, documentation, tests, and embedded UI bundles. It does not change CLI routes, APIs, authentication policy, protected metadata behavior, release secrets, or runtime transfer semantics.
