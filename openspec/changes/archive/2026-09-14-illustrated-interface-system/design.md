# Context

The first Courier identity pass established Relay, the graphite field-manual language, and shared brand primitives. The remaining native form chrome and single repeated pose weaken that system. Courier needs a coherent control grammar and an illustration program in which every appearance of Relay has a specific operational job.

# Decisions

## Controls are branded without sacrificing native semantics

Theme and locale selection use compact segmented button groups because their option sets are small and always visible. Form fields retain semantic input/select elements where they provide reliable keyboard, screen-reader, validation, and mobile behavior, but all browser chrome is normalized and replaced with Courier surfaces, focus rings, indicators, and states. Checkboxes render as branded switches, file inputs are exposed through a designed drop-zone action, and raw buttons share the same action vocabulary.

## Illustration is a contextual system

Relay keeps the same adult pigeon anatomy, graphite utility harness, signal-lime route tabs, orange beak, flat editorial line work, and mature proportions. Each illustration changes only the role-specific layer: dispatch navigator for the hero, field installer for distribution, cartographer for routing, inspector for safety, access controller for authentication, and operations controller for administration. Decorative art remains hidden from assistive technology and never carries required state or instructions.

## Landing illustrations form operational briefs

The landing hero remains the strongest scene. Installation, routing, and safety receive compact illustrated briefing cards with distinct compositions and supporting copy. Dense command and option tables remain illustration-free so art does not compete with operational data. The README receives a wide, text-free route panorama that works in light and dark GitHub themes.

## Generated assets remain local and auditable

All final raster assets are generated with the built-in image tool using the existing Relay asset as the character reference. Final prompts, roles, dimensions, hashes, and authorship context are recorded in the provenance manifest and notice. Build-time checks reject missing, undeclared, or stale assets, and application bundles never fetch identity assets from a remote service.

# Risks / Trade-offs

Additional raster assets increase repository and landing payload size. Scenes are therefore limited to high-value contexts, loaded through Vite's hashed assets, and kept non-essential. Custom controls add interaction code, so tests cover keyboard operation, selection state, focus visibility, disabled states, and event compatibility at the shared component boundary and in each consumer.

# Migration Plan

Create and verify the contextual illustration family, extend provenance, implement the shared control grammar, migrate every native-looking consumer, recompose the landing and README, rebuild embedded assets, run unit and browser accessibility checks, complete the full repository gate, archive the OpenSpec change, and commit once on the numbered feature branch.
