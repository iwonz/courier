## Why

Courier's current Relay artwork, signal-lime palette, terminal chrome, and four-part landing hierarchy compete with the product's route model and make the browser surfaces feel visually dense. Courier needs one restrained, memorable identity that makes Source-to-Destination routing understandable from the first viewport and remains coherent in delivery and administration workflows.

## What Changes

- Replace Relay with Vector, a geometric moth navigator, and replace the graphite/lime identity with a carbon, chalk, and burnt-orange aerospace-editorial system.
- Combine the landing hero and route explorer into one interactive first section, followed only by installation and the generated command/option reference.
- Replace segmented theme and locale selectors with single cyclic controls backed by one shared preference controller.
- Remove pointer refraction and terminal framing, replacing them with static proximity-loaded scenes, neutral workbench surfaces, and compact command readouts.
- Redesign delivery and administration around the same workbench grammar without changing their guarded APIs or security boundaries.
- Replace every branded repository asset, update provenance and documentation, and retain strict bundle, image, coverage, and browser acceptance gates.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `project-landing`: Establish the three-section Vector landing and combined route instrument.
- `ui-kit`: Establish the Vector identity, cyclic preferences, neutral workbench, static scene loading, and revised command readout.
- `web-deliveries`: Replace terminal presentation with the destination workbench while retaining metadata isolation and API behavior.
- `admin-ui`: Replace terminal presentation with a selectable operations workbench while retaining authoritative guarded control.
- `cross-platform-acceptance`: Verify the new identity, preference, route, responsive asset, performance, and security behavior.

## Impact

This change affects browser UI source, shared assets, embedded builds, runtime localization, repository branding, documentation, OpenSpec baselines, and browser acceptance. It does not change the public CLI contract, endpoint semantics, transfer engine, HTTP APIs, authentication model, release channels, or secret handling.
