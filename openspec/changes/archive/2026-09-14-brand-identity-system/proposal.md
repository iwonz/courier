# Change: Establish the Courier brand identity system

## Why

Courier's browser surfaces are functionally complete but still read as a collection of generic product pages. The project needs a coherent, mature identity that makes transfer state, trust, and operational control immediately legible while remaining approachable to people who do not live in a terminal.

## What Changes

- Define an English brand manual for positioning, voice, vocabulary, visual language, accessibility, and prohibited treatments.
- Introduce Relay, an original courier-pigeon field operator, as a restrained product guide and state communicator.
- Evolve the shared UI kit into a graphite utility system with signal-lime route cues, operational typography, route motifs, shared brand primitives, and consistent responsive behavior.
- Redesign the landing page as a concise dispatch brief, the delivery UI as a focused transfer terminal, and the admin UI as an operations control room.
- Refresh the English and Russian product copy without changing route behavior, security boundaries, or credential handling.
- Replace stale identity imagery, record deterministic provenance, rebuild embedded assets, and verify every browser surface in supported themes, locales, and viewports.

## Impact

This change affects presentation, product language, and local static assets. It does not add commands, endpoints, telemetry, external services, repositories, runtime dependencies, or new release credentials.
