# Administration UI

Courier ships a local administration application for inspecting data servers and deliveries, stopping a selected UUID, and editing delivery policy with optimistic version checks.

```sh
courier ui start
courier ui start --background
courier ui start --background --listen 127.0.0.1:9090
courier ui stop
```

The default address is `http://127.0.0.1:9090/`. Only literal loopback IPv4 and IPv6 addresses are accepted. A capable interactive terminal prints a QR for the exact displayed URL after the readiness panel; redirected output, `TERM=dumb`, and terminals too narrow for the complete code keep only the stable text URL. QR rendering does not change loopback reachability: a phone cannot open a `127.0.0.1` Courier UI running on another computer.

A foreground start prints readiness after both listeners and private state are ready, then runs until interruption or `courier ui stop`. A verified `ui stop` from another Courier process prints a neutral stopped result and makes the initiating command exit `0`; Ctrl+C remains an interrupted exit `130`. `--background` starts the same embedded server in a detached internal process, prints the ready URL and administration UUID, returns only after its UUID-bound IPC handshake succeeds, and survives terminal closure. It ends through `courier ui stop`, a fatal process failure, or process termination.

## Singleton and process authority

There is at most one administration process per user. Startup is serialized by a private lock. Its `0600` atomic discovery file contains only a random UUID, canonical bind, private control endpoint, compatibility identifier, diagnostic PID, and start time. The PID is never used to signal a process.

Both repeated startup and `ui stop` verify the recorded UUID and compatibility over the current-user-only IPC transport. An absent state file makes stop an idempotent success. An unreachable or malformed record fails closed. The administration process never registers as a data worker, so `courier servers stop --all` does not affect it.

## Browser and API boundary

The versioned API is available only on the configured loopback listener. Every request must use the exact listener Host. Mutations must also carry the exact `http://<host>` Origin generated by the administration page. Responses send no permissive CORS headers and include no-store, content-type, framing, referrer, and content-security protections.

JSON requests are strictly decoded and bounded to 1 MiB. SSE progress has a bounded subscriber count and releases its slot on disconnect. The API returns authoritative, secret-free snapshots: it uses the registry only for discovery and verifies each data worker through private IPC. It never returns credentials, Authorization values, sessions, opaque delivery tokens, private control endpoints, compatibility fingerprints, or runtime definitions.

Policy updates include the current expected version and exactly the next policy version. A concurrent change produces HTTP `409 Conflict`; the English/Russian React application shows the conflict and asks the operator to refresh rather than overwriting it. Stop URLs are type-scoped before any IPC action, so a delivery UUID sent to a server-stop endpoint cannot stop the delivery accidentally.

The embedded administration assets are deterministic production output from [`web/admin`](../web/admin) and consume the shared React/shadcn [`@courier/ui`](../web/ui) terminal tokens, components, icons, themes, and locale selectors. Product chrome uses mark-v3; the title region uses only admin-v3. The operations console places its real API-derived counters in a metric strip and separates server navigator, selected route facts, and policy controls with flat surfaces and crisp one-pixel rules. It invents no uptime, telemetry, or monitoring chart. Square controls retain native semantics and guarded behavior. Asset freshness and exact TypeScript/TSX coverage are part of `make verify`.
